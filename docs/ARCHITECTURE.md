# StockBot architecture (end of the restructure, Phase 10)

Goal: about five strategies, each developed, tested and retired without touching the others or the shared machinery; backtest and live run the same decision code; strategy-independent validation is identical for every strategy. This file is enforced, not aspirational: `tests/unit/test_import_boundaries.py` fails the build on a violation.

## Packages (all code under `stockbot/`; the top-level `data/` folder holds files only)
| package | purpose | may import |
|---|---|---|
| `config` | shared typed config, runtime mode, logging, file locations (`paths.py`) | nothing from stockbot |
| `data` | ingestion, **read-only lake access** (`lake.py`), corporate-action adjustment, **point-in-time as-of view** (`asof.py`), shared indicators | config |
| `universe` | eligibility rules and exclusions (ASM/GSM, earnings) | config, data |
| `risk` | costs, sizing, heat/sector caps, cross-strategy arbitration, R definitions | config, data |
| `engine` | one `decide()` for backtest and live; strategy interface (Phase 6) | config, data, universe, risk, strategies (interface only) |
| `strategies` | interface and registry only; **no strategy files** (a dummy lives under `tests/`) | data (view types) |
| `backtest` | runner, simulated fills, network guard, run manifest | config, data, universe, risk, engine, strategies (registry) |
| `live` | EOD runner, tickets, state DB and journal, idempotency, scheduler, API routers | config, data, universe, risk, engine, strategies, **validation (trade-R reporting only, for the legacy analytics routers)**; its own state store; **never backtest** |
| `validation` | Max-T, prereg lock, trade-R reporting, power study, matched-random baseline, trial ledger | config, data, risk (R definitions), backtest, **engine and universe (the baseline reuses the engine stepping and the shared eligibility; reviewer decision at STOP 4)**; **never live** |
| `data_checks` | quality, calendar, corporate-action verification, pre-flight | config, data |

Also forbidden: a strategy or the engine receiving a database session/connection or importing sqlalchemy/sqlite3; any network library inside `backtest`, `engine`, `strategies`, `risk` (the network guard module is the one exception, it patches `socket`); `sys.path` edits inside `stockbot/`; one strategy importing another; any `stockbot` module importing an old top-level path (`data`, `engine_core`, `live_runner`, `backtest`, `config`, ...) unless it is an explicit entry of the temporary allowlist.

## Data rules
- `finsight.db` is never written by backtest, live decision code or validation. `stockbot.data.lake.open_lake` opens it with SQLite `mode=ro` plus `PRAGMA query_only`; a write raises. Live state goes in a separate state database (Phase 9).
- Everything above `data` reads market data only through `AsOfView(conn, as_of)`: every query is bounded by `trade_date <= as_of`, a request for a later bar raises `FutureDataError`, adjustments use only actions with `ex_date <= as_of`, raw close/volume/traded value are exposed separately from adjusted prices, and the connection is not reachable from the view.
- The market-cap gate and `shares_outstanding` are parked (KI-001); the view does not expose share counts.

## How a decision is made (one function for backtest, paper and live)
`stockbot.engine.decide.decide(as_of, state, view, strategies, shared_config, event_data, policies=, overlays=, strict=, mode=)` handles exactly ONE trading session and is pure: all market data comes through the as-of view, everything it remembers is in the plain-data `State`, it returns `(Decisions, State)` and the new State is `apply_decisions(old_state, decisions)`. Order inside a session: overlays; fills of yesterday's tickets at today's open (`engine.fills`: gap rules, slippage, per-strategy `confirm_fill`, sizing from the fill price); corporate actions then stepping of every open position through today's bar (`engine.stepping`: pending market exit, stop incl. the entry bar and with no floor at the bar's low, the policy's `step`, limit requests); eligibility (`universe.eligibility`); each strategy proposes; `risk.arbitrate` admits the proposals (per-strategy order, round-robin across strategies, a held symbol cannot be opened by another strategy). Details and rulings: `docs/restructure/ENGINE_CONTRACT.md`.
- **Backtest** (`stockbot.backtest.runner`): one `decide` per session on the read-only lake, strict mode, network guard, END_OF_WINDOW close, run manifest (config hash, strategy hashes, git SHA, data snapshot id, seed).
- **Live** (`stockbot.live`): `runner.run_eod` = mode gate (PAPER default; LIVE needs a strategy with status `live` and a `validation_ref`) -> freshness check only (ingestion is its own step) -> ASM/GSM data (fail-closed in LIVE) -> `LiveAdapter.process` (operator reports first, one `decide` per unseen session, journal) -> one ticket file per session. State lives in a SEPARATE SQLite database (`state/live_state.db`, schema versioned, append-only journal, `rebuild()` from the journal alone). No order-routing code exists (`tests/unit/test_regulatory_barrier.py`). Command lines: `scripts/run_eod.py`, `scripts/daily_health_check.py`, `scripts/check_all.py`.
- **Validation** (`stockbot.validation`): Max-T bootstrap, pre-registration lock and the hash-chained trial ledger (`validation/ledger/records`, with the family helper that records N strategies together), trade-R reporting, the matched-random baseline (`random_baseline`, `paired_stats`) built on `engine.path.simulate_ticket`, the same fill and stepping code the engine uses.

## What is where
- `stockbot/` - all code. `scripts/` - thin command-line wrappers only (they run a package module as `__main__`; every one answers `--help` without writing, tested) and `scripts/provenance/` (one-off and superseded tools kept because reports cite them; `README.md` there maps old paths to new). `data/` - reference and F9 data files only. `backtest/` - two folders of kept results and no code (`backtest/README.md`). `docs/` - this file, data/validation docs, `data_audit` reports, `archive` (old specs and plans), `restructure` (the restructure record: plan decisions, contract, inventory, config key homes, ledger manifest, removed tests, fail-before evidence, pre-live list). `ui/` - the React dashboard (untouched). `Claude_Docs/` - reviewer reports.
- Configuration: `stockbot/config/shared.yaml` (typed by `shared.py`; gates and paper criteria are shared and never overridable by a strategy). A strategy is a `StrategySpec` (id, version, params, exit policy, overlays, status, `prereg_ref`, `validation_ref`) and nothing else. `strategy_config.yaml` no longer exists; each of its 81 keys has a documented home in `docs/restructure/CONFIG_KEYS.csv` and the old values are in `docs/restructure/OLD_STRATEGY_REFERENCE.md`.
- No strategy exists in the tree: `stockbot/strategies` holds the interface, the spec schema and an empty registry; the dummy strategy, exit policies and overlay for the tests live under `tests/fixtures/dummies.py`. The old strategy and the old pipeline are in git tag `pre-restructure`.

## Tests and golden checks
`tests/unit` (fixture lake, no real database), `tests/integration`, `tests/data_integrity` (env-gated, `STOCKBOT_DATA_TESTS=1`, read-only on `finsight.db`), `tests/fixtures`, `tests/golden` (results frozen from the old code before it was deleted, with `SHA256SUMS`). `py scripts/check_all.py [--data] [--final]` runs: G1 unit suite, G3 fixture baseline (the hand-derived trade through the engine), G5 import boundaries (+ every module imports alone), G6 engine parity / lookahead / idempotency / determinism / isolation / strict mode / baseline reuse, and with `--data` G2 (real-database tests: the frozen 120 as-of samples bit-exact, the engine scan 764 -> 267, the 57 verification rows through the view). `--final` also requires the import-boundary allowlists to be empty. G4 (finsight.db unchanged) is a sha256 / mtime comparison.
