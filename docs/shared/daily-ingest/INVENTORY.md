## 3. How a day's lake rows are built today (what the daily job must reproduce)
- **EQ series only**: `parse_bhavcopy` (`ingest_raw_bhavcopy_range.py:73` to `:100`) keeps `SctySrs`/`SERIES == EQ`; columns by name from either layout (`TckrSymb`/`SYMBOL`, `OpnPric`/`OPEN_PRICE`, ..., `TtlTradgVol`/`TTL_TRD_QNTY`); non-numeric prices drop the row, volume NaN becomes 0; `symbol` stripped, not upper-cased. A file whose own date (`DATE1`, `TIMESTAMP`, `TRADDT`) differs from the requested date is rejected (`:103` to `:114`, `:142`): NSE answers 200 with the previous session's file on holidays.
- **Raw, not adjusted**: the lake holds raw prices; adjustment is applied on read from `corporate_actions_log` (`stockbot/data/asof.py:176` to `:203`; `adjustments.py`).
- **Promotion from staging to lake** (F2): `INSERT INTO market_data_lake (symbol, trade_date, open_raw, high_raw, low_raw, close_raw, volume_raw, exchange, created_at, source, loaded_at) SELECT symbol, trade_date, ..., 'NSE', now, 'nse_bhavcopy_raw', now FROM market_data_lake_staging WHERE ... series='EQ'` (`f2_swap.py:129` to `:139`). `isin`, `prev_close`, `series` stay in staging only.
- **Index rows**: two rows a session, `NIFTY50_INDEX` and `INDIA_VIX`, volume 0, OHLC from the NSE index file `ind_close_all_DDMMYYYY.csv` (columns `Index Name`, `Index Date`, `Open/High/Low/Closing Index Value`) or Yahoo; the Bhavcopy has no index. Without them the date is not a session (calendar) and `check_freshness` fails.
- **Renames**: F2 relabelled the pure-rename segments of `data/reference/isin_symbol_map.csv` (353,088 rows) to the latest name inside the lake (`f2_swap.py:171`, `source_symbol` keeps the traded name). `data/reference/symbol_links.csv` (41 pairs, built by `scripts/build_symbol_links.py` from the isin map and the lake; read by `stockbot/data/symbol_links.py:68`; switch `data.symbol_links_enabled`) is applied on read for the boundaries that remain. New rows of a stock renamed after 2026-10-16 would sit under the new traded name, with no link until one is added.
- **Corporate actions**: events (SPLIT/BONUS/DIVIDEND/RIGHTS/MERGER/DEMERGER/OTHER, ratio columns, notes, evidence tier), `UNIQUE(symbol, ex_date, action_type)`, keyed to the lake symbol holding the pre-ex prices (`lake_symbols.py:8`), feed symbol kept in `notes` (`feed_symbol=<name>;`).
- **Reference files read at run time** (in the repo, not in the DB): `data/reference/fund_etf_symbols.csv` (512 rows; `asof.py:51`; excludes ETFs/funds from eligibility; built from staging ISINs starting `INF`), `sector_map.csv` (501 symbols; `sector_map.py:15`; unmapped symbols are their own sector), `symbol_links.csv`, `special_sessions.csv` (weekend sessions, used by `tests/data_integrity/test_calendar_integrity.py`).
- **Eligibility needs** (`stockbot/universe/eligibility.py:22` to `:41`): bars in the lake (listing age counted in lake bars; names trading on the lake's first day count as seasoned), raw 20-session ADTV, the fund list, and an ASM/GSM set passed in by the caller. The earnings tables are used only by strategies that ask for `results_within` (riskadj_momentum does not).

## 5. What the live package needs for a new date and a paper-status strategy
- `run_eod` (`runner.py:128`): `refuse_memory_view`; mode gate (`strategies_for_mode`, `:64`: PAPER runs strategies with status `paper` or `live`; a `research` strategy never runs); `open_lake(lake_path())` (`STOCKBOT_DB`, default `<repo>/finsight.db`); `check_freshness`; ASM set from `asm_gsm_daily_snapshot` for the date (`:96`; PAPER notes a missing day, LIVE refuses); a `StateStore` at `state_db_path()` (`STOCKBOT_STATE_DB`, default `<repo>/state/live_state.db`, **relative to the worktree the code runs from**) initialised with `runtime.paper_start_equity` 1,000,000 on first use (`:143`); `LiveAdapter.process`; tickets to `tickets_dir()`.
- **The default book is empty** (`runner.py:60` `default_book`, and `eod_cli.py:24` passes `book or default_book()`): `py scripts/run_eod.py` processes nothing until a book with strategies and policies exists. A book needs `Book.from_strategies([strategy], extra_policies=[TrailingAtr3Floor8()])` because the library does not know the strategy-owned policy (`runner.py:55` `Book.from_strategies`; `LiveAdapter` looks the policy up by `spec.exit_policy`, `adapter.py:48`). Nothing in the tree builds that book for riskadj_momentum.
- **riskadj_momentum's spec says `status="research"`** (`stockbot/strategies/riskadj_momentum/strategy.py`, `SPEC`); PAPER mode skips it. Changing `status` to `paper` changes `SPEC.config_hash()` (72dbec2c... today); params stay.
- `LiveAdapter.process` (`adapter.py:59` to `:75`): processes every session after the stored state's `as_of` up to the date, one `decide` per session in `mode="live"`; **on the first run it processes only the last session** (`:69`, "no history to replay"). `decide` already carries the symbol links and the 20-session stale exit (stale-positions merge). A date already journaled changes nothing (idempotent).
- The strategy trades only on the first session of a calendar month (`is_signal_session`): the first paper signal after the data is current is the first session of 2026-12.
- The paper pass marks: owner marks (max drawdown below 35%, at least 30 closed trades) against `paper_criteria` in `stockbot/config/shared.yaml:85` to `:92` (min_days 90, min_closed_trades 60, max_expectancy_gap_r 0.25, max_win_rate_gap_pts 12.0, min_profit_factor 1.2, max_drawdown_pct 12.0, max_skipped_ticket_rate 0.40). The only consumer of `paper_criteria` is `stockbot/live/paper_report.py:56`, which reads the legacy `trade_analytics_log` table of the lake (no writer exists since 337f71d), so it cannot evaluate a paper run on the new state store.
- Health check (`live/health_check.py`): data older than 4 days, snapshot versus journal rebuild, state behind the lake's latest session.
- Alerts: `live/scheduler.py:_send_failure_alert` shows a Windows toast through `winotify`.
- The machine: a laptop (`PCSystemType` 2), time zone India Standard Time, sleep state "Standby (S0 Low Power Idle) Network Disconnected" (the network is off while asleep), Hibernate and Fast Startup available.
