# Daily data update: build plan (stage 1, design only)

Small stages, each its own commit and approval. Every stage: unit tests on fixture lakes only (never `finsight.db`), plain commits without trailers, snapshot 1's sha256 `dcade465...b752` checked before and after, G1 at the end of any stage that touches a shared file. New code lives in a new package `stockbot/data/daily/` (data package: network allowed, no import from `live`, `engine` or `backtest`) and in new scripts; the shared files an individual stage touches are named. **Nothing downloads before stage 9.**

Everything else is new files. Standing proofs for every stage: (a) snapshot 1 is never opened for writing: it carries the OS read-only attribute from stage 1 and its sha256 is checked before and after the stage; (b) the working file is a different file, found only through `STOCKBOT_DB` set by the task, and the default path still resolves to snapshot 1; (c) the new package imports nothing from `engine`, `backtest` or `strategies` (the existing import-boundary test is extended to `stockbot/data/daily`); (d) no research script reads the working path (guard of stage 7).
