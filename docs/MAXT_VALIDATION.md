# Analysis and decision requested (team write-up, 2026-11-06)

**What the simulation shows**

1. *Independent weekly data (rho = 0):* the procedure is correctly sized (4.0–5.5%). The implementation is not broken.
2. *Autocorrelated weekly data:* the pre-registered claim "FWER <= 0.05" is **not** met. Single block-4 test: 6–7% at rho 0.2, 9–11% at rho 0.4, 15–17% at rho 0.6. The pre-registered **dual rule** (significant at block 4 AND 8) helps but still over-rejects: ~5–6% / 7–8% / 10–11% in the same cases. Block 2 is clearly invalid at rho >= 0.2.
3. *Long holds (the entry-week statistic with overlapping trades, MA(L)):* L=4: dual 9%; **L=12 (about a quarter): dual ~20%, block-4 ~35%.** For 1–3-month holds the weekly entry-week statistic cannot control family-wise error with 4- or 8-week blocks, because trades entered in adjacent weeks share their holding period and the dependence extends to roughly the hold length.
4. *Power is low:* with 250 weeks and an edge of 0.3 weekly SDs the dual rule detects it 81–100% of the time under AR(1), but only 41% with L=12 overlap; at 0.15 SD it is 21–50%. Longer holds lose power as well as size.
5. Simulation caveats: B = 2,000 draws per replication (production uses 10,000; size is not materially affected), 600 replications per cell (MC s.e. about 1 point near 5%, 1.5 points near 15%), common-factor cross-correlation 0.5, Gaussian shocks.

**Decision needed (owner + reviewer) — recommendation first**

* **Option C (recommended): switch the statistic for long-hold strategies to portfolio-level periodic returns** — e.g. monthly (calendar-realised) net return of the strategy portfolio minus the matched baseline portfolio, tested with the same Westfall-Young step-down over circular blocks measured in months. This removes the entry-week/overlap problem at its source (returns are attributed to the period in which they accrue), keeps K-config multiplicity control, and makes the unit of dependence a month. The size/power of that statistic must be re-validated with this same script (new DGPs: AR(1) on monthly returns, ~60–120 observations) before use.
* Option A: fix the procedure for weekly entry statistics — use blocks at least as long as the hold (13–26 weeks). Preserves the current pipeline but leaves few effective blocks (W/b ~ 10–20) and sharply lower power.
* Option B: tighten the pre-registered threshold (e.g. calibrated alpha so the dual rule has 5% size at the assumed rho/hold). Needs a stated dependence assumption that the data cannot confirm in advance; least preferred.

For the old breakout family (holds mostly < 20 sessions, rho ~0.1–0.25 measured) the dual rule's true size is roughly 5–7%, so the earlier "no candidate" verdict is not undermined; the concern is the new 1–3-month family.

Nothing in `engine_core/max_t_bootstrap.py` was changed in F9 (only the test was made deterministic). Implementation of the chosen option, and its validation run, wait for the decision.

**Test change:** `tests/unit/test_max_t_bootstrap.py::test_empirical_fwer_with_ar1_autocorrelation` used `seed=None` bootstraps, so it was non-deterministic (it failed with 12.5% > 12% in one run and passed in others). It is now fully seeded, documents the measured sizes (block-4 <= 15%, dual <= 12% at rho 0.4, 80 weeks — measured ~11% and ~8%) rather than claiming 5% control, and a second test asserts reproducibility.
