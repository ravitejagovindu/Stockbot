## The override design
- `stockbot/config/risk_override.py`: env `STOCKBOT_RISK_PCT`, **default OFF** (unset or empty: `apply` returns the same config object, no block anywhere, all outputs byte-identical; the existing golden and fixture tests pass unchanged). Accepted 0.1 to 1.0; anything else (also nan, inf, text) raises `RiskOverrideError`. The value is printed to stderr at the start (`RISK OVERRIDE ON: ...`). It replaces only `portfolio_risk.max_loss_pct_per_trade` in a copy of the config; costs, caps, slippage, gates and equity are untouched.
- (c) Same value everywhere: the research scripts, the baseline scripts (their random draws are sized by the same `fill_ticket` call; a test records `risk_pct` 0.5 for every draw), and the gates scripts (implied-return line) all read the same variable. **The baseline refuses a value different from its run's manifest** (`RiskOverrideError`, in both directions).
- (d) Recorded: run manifest `risk_override` {env, value, base value from shared.yaml, note}; `baseline_meta.json` `risk_override`; written only with the override on.
- (e) Paper and live: `stockbot.live.runner.run_eod` refuses with `ModeError` when `STOCKBOT_RISK_PCT` is set (so the scheduler and `eod_cli` are covered; `eod_cli` prints REFUSED and returns 2).
- (f) `scripts/validate_family.py`: new `member_risk_override(run_dir)`; `validate_family` raises `ValueError` ("members were run with different risk overrides ... a mixed family is refused") if the members' manifests disagree (None counts as the shared.yaml value).
- **(g) `shared_config_hash` and the gates script.** The manifest's `shared_config_hash` is computed from the config actually passed to the run, so **with the override on it differs** from a run without it (the one number `max_loss_pct_per_trade` is part of the hash; a test shows the hashes differ and that the plain value is still `da459624...8956248`); the `risk_override` block carries the base value so the difference is explained. `shared.yaml` and its hash do not move, so no old result's hash changes. The **gates hash does not move** (`e9b6407f...8054`, asserted with the override on): it covers only `validation_gates`. The gates scripts read the gate limits unchanged and use the override only for the non-gating implied-annual-return line (trades per year x expectancy x risk per trade), which then shows 0.5. The benchmark scripts read only the risk-free rate and are unchanged.
